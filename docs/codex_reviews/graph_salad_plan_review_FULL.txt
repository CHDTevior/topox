### 1. TreeIK logic chain review (PRIMARY)

The current TreeIK path is logically aligned with the locked design: it avoids free Cartesian joint prediction by decoding rotations, then hard-FK positions (`fk_one`: child position is parent position plus rotated rest offset, [src/models/treeik_decoder.py:87-96](src/models/treeik_decoder.py:87)). That preserves bone/edge lengths by construction; eval confirms edge/bone metrics are hard-FK-driven ([README.md:93-99](README.md:93)).

(a) `RestFiLM` conditions only on projected `rest_tensor` offsets (`rest_proj(rest_tensor)` then FiLM), not GT motion, so it is geometry conditioning and leak-free for target-skeleton generation ([src/models/treeik_decoder.py:158-170](src/models/treeik_decoder.py:158), [src/models/treeik_decoder.py:274](src/models/treeik_decoder.py:274)).

(b) `TreeGraphAttention` uses dense per-sample `adjacency/geodesic_dist` biases and masks padded keys, then zeroes padded queries ([src/models/treeik_decoder.py:194-210](src/models/treeik_decoder.py:194)). It does not consume `edge_index/edge_mask`; Graph-SALAD must convert dynamic graph metadata to dense `[B,J,J]` or add an adapter.

(c) FK handles variable J through `parents_list[b]`, truncates to `Jpad`, validates single root index 0 and parent-before-child order, and zeros padded joints ([src/models/treeik_decoder.py:99-114](src/models/treeik_decoder.py:99)). Hidden assumption: every skeleton and any future pooled/unpooled order must preserve root=0 and topological parent-before-child order.

(d) 6D-to-rot uses standard Gram-Schmidt columns and geodesic loss clamps acos input for stability ([src/models/treeik_decoder.py:57-63](src/models/treeik_decoder.py:57), [src/models/treeik_decoder.py:299-311](src/models/treeik_decoder.py:299)). Caveat: near-colinear 6D vectors can produce non-orthonormal matrices; not fatal, but monitor.

(e) `TopoFKTreeIKDecoder.forward` correctly consumes `parents_list`, `rest_tensor`, dense graph tensors, masks, and `fps` across batch ([src/models/treeik_decoder.py:269-288](src/models/treeik_decoder.py:269)). Current train/eval pass source `frame_mask` into target decode ([scripts/train.py:468-473](scripts/train.py:468), [scripts/eval.py:413-416](scripts/eval.py:413)); safe for same-clip self-recon, but Graph-SALAD should pass the batch/target frame mask explicitly.

Verdict: GOOD-TO-REUSE
