## 1. F1 ckpt-compat

Verdict: SEALED for the stated round-2 scope, with a real-ckpt step-2 caveat.

GraphMotionVAE now registers the baseline-compatible modules at the expected
top-level names:

- self.encoder is a SkeletonEncoder at src/models/graph_salad/vae.py:113-123.
- self.slot_norm is SlotNorm at src/models/graph_salad/vae.py:123.
- self.decoder is the raw MotionDecoder at src/models/graph_salad/vae.py:156-170.
- self.treeik_head is separate ModuleDict state under treeik_head.* at
  src/models/graph_salad/vae.py:171-188.

Baseline Model registers the same baseline key surface:

- self.encoder at src/models/model.py:76-86.
- self.slot_norm at src/models/model.py:88-91.
- self.decoder at src/models/model.py:93-101.

The SlotNorm key prefix is slot_norm.norm.* because SlotNorm contains
self.norm = nn.LayerNorm(d_model) at src/models/slot_norm.py:25-27. This matches
the baseline Model and the VAE because both use the same SlotNorm class.

The round-2 test does construct a baseline Model state_dict rather than a purely
handwritten dict: tests/test_vae.py:148-157 constructs Model, tests/test_vae.py:159-168
constructs GraphMotionVAE with matching dims, and tests/test_vae.py:170-184 loads
baseline.state_dict() into the VAE with strict=False, asserts unexpected_keys is
empty, and restricts missing keys to pool.*, dist.*, treeik_head.*, or unpool.*.

Runtime probe confirms the test's core claim:

- baseline prefixes: decoder, encoder, slot_norm
- VAE prefixes: decoder, dist, encoder, pool, slot_norm, treeik_head
- load_state_dict(baseline.state_dict(), strict=False): unexpected=[]
- missing prefixes: dist, pool, treeik_head

That seals F1 for "baseline Model state_dict loads into VAE without unexpected
keys." It also verifies that the previous decoder.base.* nesting problem is gone:
the VAE decoder is MotionDecoder directly at src/models/graph_salad/vae.py:163-170.

Caveat: this is not yet a real checkpoint-load gate. The current test uses an
in-process synthetic Model state_dict, not runs/L6_anchor_h100_seed42/best_model.pt
or runs/baseline_noKslot_ep399/last_model.pt. The real L6 and ep399 model_state_dicts
I probed contain slot_assignment.* unexpected keys. That is consistent with the
existing tolerant loader policy in scripts/eval.py:359-386 and scripts/animate.py:58-87,
but it is not covered by tests/test_vae.py. If step 2 intends to reuse the trained
topofk_state_dict, there is a separate mismatch: scripts/train.py:374-375 constructs
TopoFKTreeIKDecoder(model.decoder, d_model_actual) without passing n_heads, so it
uses the TopoFKTreeIKDecoder default n_heads=8 at src/models/treeik_decoder.py:247-255,
whereas GraphMotionVAE builds TreeIKBlock(..., n_heads, ...) from the base VAE
n_heads at src/models/graph_salad/vae.py:176-181. The saved ep399 TreeIK attention
bias weights are shape [8, 1]; a VAE built from the L6 base args has n_heads=4
and expects [4, 1]. This does not break F1 if treeik_head is intentionally fresh,
but step 2 must state that policy explicitly.

## 4. New R12 from restructure

Verdict: no new blocker found in the requested categories, with one hardening
note and one step-2 checkpoint-policy risk.

ModuleDict / ModuleList order:

- treeik_head is built as an nn.ModuleDict at src/models/graph_salad/vae.py:176-188.
- blocks is an nn.ModuleList at src/models/graph_salad/vae.py:178-181.
- decode iterates self.treeik_head["blocks"] at src/models/graph_salad/vae.py:345-349.
- The iteration order that matters is the ModuleList order, not ModuleDict key
  traversal. Runtime environment is Python 3.12.9 and PyTorch 2.10.0+cu128; both
  preserve module insertion/list order. Verdict: deterministic.

Double registration:

- The base decoder is registered once as self.decoder at src/models/graph_salad/vae.py:163-170.
- TreeIK head modules are separate under self.treeik_head at src/models/graph_salad/vae.py:176-188.
- Runtime named_parameters() probe found duplicate_param_objects=[].
- Verdict: no parameter double-registration found.

Device/dtype:

- Decoder and treeik_head are both registered submodules of GraphMotionVAE, so
  model.to(device/dtype) moves them together.
- decode sends decoder output feats into treeik_head modules directly at
  src/models/graph_salad/vae.py:336-351, then into fk_persample at
  src/models/graph_salad/vae.py:353-354.
- Normal project path is float32 tensors; no immediate decoder/treeik dtype
  mismatch was found.
- Hardening note: _identity_assignment constructs float32 assignments explicitly
  at src/models/graph_salad/vae.py:50-56. That is fine for the current float32
  path, but it is not dtype-polymorphic if a future double/mixed-precision path
  expects assignment dtype to track h_fine.

Silent fallback:

- No try/except exists in src/models/graph_salad/vae.py.
- encode/decode/forward do not swallow errors; they rely on the called modules'
  validation and PyTorch failures.
- Verdict: no silent fallback found in the VAE.

Step-2 checkpoint-policy risk:

- Existing eval/animate derive baseline Model dimensions from the init checkpoint
  when loading ep399: scripts/eval.py:361-373 and scripts/animate.py:62-75.
  A naive VAE built from defaults will not match ep399's model_state_dict, because
  ep399 args only retain init_ckpt and not the base dims.
- If step 2 only loads encoder/slot_norm/decoder and initializes VAE-only modules
  fresh, then the current VAE state surface can support that with an explicit
  policy accepting slot_assignment.* unexpected and dist/pool/treeik_head missing.
- If step 2 intends to reuse ep399 topofk_state_dict, current VAE treeik_head
  cannot load it unless TreeIK n_heads is made compatible with the saved default
  8-head TopoFKTreeIKDecoder. This is the remaining concrete shape risk.

## 5. M1.3 step 2 GO / NO-GO

Verdict: GO only to the real-checkpoint smoke-test substep; NO-GO for training
script wiring until that smoke test is added and passes.

Reasoning:

- F1's local module-prefix fix is real and removes the decoder.base.* blocker.
- F2's forward-bitwise objection is not a PLAN_GAP_REPORT section-6 requirement.
- F3's runtime validation implementation is present, but the tests do not cover
  the three round-1 validation fixes.
- The existing ckpt-compat test is synthetic. It proves the class surfaces are
  aligned for a freshly constructed Model, but it does not prove the real L6 or
  ep399 ckpt schema.
- Real checkpoint loading has policy details that tests must lock before training:
  slot_assignment.* unexpected keys, dims derived from ep399 init_ckpt, and whether
  topofk_state_dict is intentionally ignored or mapped into treeik_head with
  n_heads compatibility.

Recommended immediate fixes before wiring training:

1. Add three F3 regression tests in tests/test_vae.py for dropout, d_model%n_heads,
   and invalid no-pool T.
2. Add a real-checkpoint smoke test or standalone preflight script that loads:
   - runs/L6_anchor_h100_seed42/best_model.pt
   - runs/baseline_noKslot_ep399/last_model.pt
   using the same dimension-derivation policy as eval/animate.
3. Explicitly decide one TreeIK policy:
   - fresh treeik_head is allowed and topofk_state_dict is ignored, or
   - treeik_head loads ep399 topofk_state_dict, in which case VAE needs a separate
     n_treeik_heads defaulting to 8 or another compatibility mapper.
