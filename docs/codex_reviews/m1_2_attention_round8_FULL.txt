## validate_inputs=False bypass safety
Net: safe-with-contract, unsafe as a public unchecked API.

Concrete invalid bypass behavior:
- `adjacency > 1` or `adjacency < 0`: computes finite but semantically wrong biased attention. Out-of-contract.
- `geodesic_dist` NaN: propagates NaN to output. I verified `validate_inputs=False` returns `has_nan=True`.
- `geodesic_dist == -Inf`: `_compute()` treats it like `+Inf` at `attention.py:L346-L347`, silently neutralizing it. Out-of-contract.
- all-False `node_mask`: returns finite garbage attention, not NaN. I verified finite `(1, 4, 16)` output.
- batch singleton mismatch, e.g. `x` has `B=2` while adjacency/geodesic/mask have `B=1`: silently broadcasts and returns `(2, 4, 16)`. This is the biggest footgun, but default validation catches it.
- integer/bool adjacency or mask dtype mismatch: usually crashes in `Linear` or `masked_fill`, not silent.
- `d_model` not divisible by heads: impossible after constructor guard at `attention.py:L85-L88`.

I do not count this as NEEDS-FIX because the flag is explicitly documented as "caller asserts inputs already validated" at `attention.py:L134-L138`. Hot-path callers must validate once before entering timestep loops.
