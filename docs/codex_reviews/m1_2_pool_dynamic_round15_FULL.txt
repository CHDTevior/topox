Q2. Is there a concrete 23rd R12 that survives?

Answer: Yes. The override path silently violates the documented anchor_indices output sentinel contract for inactive slots.

Repo-truth contract:
- pool_dynamic.py:39 documents output anchor_indices as "[B, C_max] long, -1 for padded".
- pool_dynamic.py:164-179 implements the rule-based path that way: anchor_indices is initialized to -1 and only active slots are overwritten.
- pool_dynamic.py:745-758 validates all override anchor_indices are in [-1, J), so invalid garbage such as 9999 raises.
- pool_dynamic.py:765-815 validates only active slots for nonnegative, valid-joint, strictly ascending, root-first anchors.
- No check enforces anchor_indices[b, c] == -1 when coarse_mask[b, c] is False.
- pool_dynamic.py:850-860 returns anchor_indices unchanged.

Concrete runnable trace:

python - <<'PY'
import torch
from src.models.graph_salad.pool_dynamic import DynamicGraphPool

D, T, J = 16, 4, 6
pool = DynamicGraphPool(d_model=D, max_coarse=4, local_radius=5)
jf = torch.randn(1, T, J, D)
se = torch.randn(1, J, D)

adj = torch.zeros(1, J, J)
for j in range(1, J):
    adj[0, j, j - 1] = 1.0
    adj[0, j - 1, j] = 1.0

geo = torch.zeros(1, J, J)
for i in range(J):
    for j in range(J):
        geo[0, i, j] = abs(i - j)

jm = torch.ones(1, J, dtype=torch.bool)
fm = torch.ones(1, T, dtype=torch.bool)

# Slot 3 is inactive, but contains a valid joint id 0 instead of the documented -1 sentinel.
anchor_indices = torch.tensor([[0, 2, 5, 0]], dtype=torch.long)
coarse_mask = torch.tensor([[True, True, True, False]])

out = pool(
    jf, se, adj, geo, jm, fm,
    anchor_indices=anchor_indices,
    coarse_mask=coarse_mask,
)
print("returned_anchor_indices=", out["anchor_indices"].tolist())
print("pooled_mask=", out["pooled_mask"].tolist())
print("inactive_assignment_abs_sum=", float(out["assignment"][0, :, 3].abs().sum()))
print("inactive_embedding_abs_sum=", float(out["pooled_skeleton_embeddings"][0, 3].abs().sum()))

Why this is R12:
- The core tensors are masked, so this does not immediately corrupt pooled_features or pooled_skeleton_embeddings.
- But the returned metadata is wrong by the module's own output contract: slot 3 is padded/inactive, yet the sentinel is 0, not -1.
- A downstream module that consumes anchor_indices by sentinel, or logs/serializes anchor metadata, sees an active-looking root id in an inactive slot.
- This is a silent wrong output / silent metadata fallback. It should either fail loud or the output contract must be explicitly redefined.

Minimal required fix:
- In the override path, after coarse_mask prefix validation, reject inactive slots that are not -1:
  inactive = ~valid_anchor_mask
  if (anchor_indices[b][inactive] != -1).any(): raise ValueError(...)
- Add a regression test, e.g. test_inactive_anchor_slot_must_be_minus_one_raises:
  anchor_indices = [[0, 2, 5, 0]], coarse_mask = [[True, True, True, False]]
  should raise an informative error mentioning inactive/padded coarse slots and -1 sentinel.
