Q2. 12th R12 lurking?
================================================================================

New R12 found: unbounded adjacency magnitude.

Concrete malformed input: B=1, N=4, d_model=16, all nodes valid, line-graph
adjacency with edge entries `1_000_000.0` instead of `1.0`, and geodesic
equal to the correct line-graph hop distances. Current code accepts it
because adjacency is finite, non-negative, symmetric, zero-diagonal, and
Floyd only checks `adjacency > 0`, so cross-consistency still passes:
attention.py:179, graph_utils.py:128.

Why it corrupts behavior: `adjacency_bias(adjacency.unsqueeze(-1))` injects
raw magnitude into attention logits at attention.py:318, then
`scores = scores + topo_bias` at attention.py:320. This turns an otherwise
identical graph topology into an arbitrary softmax-saturating bias.
Verified smoke case: `adj * 1_000_000` was accepted and changed output by
max abs diff about `0.74` versus binary adjacency.

This is malformed relative to local producers: raw `GraphMotionBatch`
requires binary adjacency (batch.py:426), and hard coarse adjacency is
binarized (graph_utils.py:246). Fix should enforce a bounded adjacency
contract, likely valid-pair values in `[0, 1]`, unless `pool_dynamic.py`
deliberately defines and normalizes another range.

Q5. Performance — keep always-on or add toggle?
================================================================================

Recommendation: add-toggle.

Always-on Floyd is fine for a single module call at `N<=160`, but not fine
as a repeated denoiser hot-path check across many diffusion steps and
layers. It is also a Python-loop Floyd with `N` iterations, so on GPU it
is not just "4M ops"; it is repeated kernel work per forward. Keep
validation default-on, but add an explicit `validate_inputs: bool = True`
path so callers can validate once at the batch/pool boundary and skip
repeated Floyd checks in hot loops.
