3. R12 / Failure-Loud Gaps

The smoke catches crash-class failures across dynamic/deterministic/none, but
it is thin as an R12 harness.

It does not directly assert deterministic anchor invariants. The deterministic
pool has root/sorted/prefix checks in override mode and parent/adjacency checks
in [pool_deterministic.py](/scratch/ts1v23/workspace/noKslot_clean/src/models/graph_salad/pool_deterministic.py:399),
and rule anchors come from
[graph_utils.py](/scratch/ts1v23/workspace/noKslot_clean/src/models/graph_salad/graph_utils.py:368).
But `GraphMotionVAE.encode()` does not expose `anchor_indices`, so the smoke
cannot verify root-first, sorted unique anchors, active counts, or prefix
`coarse_mask`.

Dynamic pad-leak is only partially covered. The batch uses random padded
motion/skeleton rows, which helps, but the smoke does not poison padded rows
with large sentinels and compare valid outputs/loss under fixed seed. So a
finite but wrong valid-output dependency on padded rows could pass.

No-pool aux behavior is not asserted. The `none` branch correctly returns zero
aux losses in [vae.py](/scratch/ts1v23/workspace/noKslot_clean/src/models/graph_salad/vae.py:291),
and `forward()` wraps them as `pool_aux_outputs` in
[vae.py](/scratch/ts1v23/workspace/noKslot_clean/src/models/graph_salad/vae.py:407).
But the smoke would not fail if this path returned an empty aux list.

`gt_pos = motion_features[..., :3]` is correct: `UnifiedMotionDataset` defines
`motion_features = [local_pos(3), velocity(3)]` in
[unified_dataset.py](/scratch/ts1v23/workspace/noKslot_clean/src/data/unified_dataset.py:4)
and concatenates that layout in
[unified_dataset.py](/scratch/ts1v23/workspace/noKslot_clean/src/data/unified_dataset.py:133).

Random `motion_features`, `skeleton_features`, root, and rotations are fine for
wiring smoke, but this is not a real motion reconstruction test. It validates
tensor plumbing, masks, finite loss, and gradients, not data-scale behavior or
meaningful reconstruction.
