FOUND: parent topology can silently disagree with adjacency/geodesic in the
direct `parent_indices` path.

Code path:
  pool_dynamic.py:670-683 only checks parent_indices list length. Then
  pool_dynamic.py:688-691 selects anchors from parent_indices. Floyd consistency
  checks only adjacency vs geodesic_dist at pool_dynamic.py:621-638; it never
  checks parent_indices matches adjacency. find_anchors_rulebased validates
  that the parent list is a tree at graph_utils.py:406-413, then derives anchors
  from that tree at graph_utils.py:421-457. Batch-level construction does have
  the missing consistency guard at batch.py:426-472, but direct
  DynamicGraphPool.forward bypasses it.

Concrete input:
  J=6, line adjacency/geodesic, joint_mask=all True, max_coarse=6,
  local_radius=5, but pass star parents [-1,0,0,0,0,0] instead of line parents
  [-1,0,1,2,3,4].

Predicted failure:
  No ValueError. Floyd passes because geodesic matches line adjacency. Anchor
  selection uses the star and emits [0,1,2,3,4,5] instead of line anchors
  [0,5]. The model now pools using anchor topology from one graph and
  distances/adjacency from another, silently corrupting the pool geometry.

Additional hardening gap:

  max_chain_chunk_len, temporal_stride are annotated as ints at
  pool_dynamic.py:88-92, but only value-compared at pool_dynamic.py:106-113.

  pool_dynamic.py:279-293; max_chain_chunk_len=float("nan") passes both
