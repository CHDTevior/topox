Q2. 20TH R12 SEARCH

FOUND: padded adjacency rows/cols are accepted by DynamicGraphPool and corrupt
the mincut denominator.

Why this is R12:
  - DynamicGraphPool accepts joint_mask-padded inputs directly, not only
    GraphMotionBatch objects.
  - Padded joints are explicitly meant to be ignored. Assignment and pooled
    graph do ignore them.
  - The mincut denominator does not ignore padded adjacency edges incident to
    valid joints, because degree is computed on the raw adjacency.
  - This changes aux_losses["mincut"] while leaving assignment and pooled graph
    unchanged, so it is silent loss corruption.

Source trace:
  - pool_dynamic.py:488-516 validates adjacency finite/symmetric/diagonal/range,
    but does not require padded rows/cols to be zero under joint_mask.
  - pool_dynamic.py:330 computes S^T A S. Because P rows for padded joints are
    zero, padded endpoints do not affect the numerator.
  - pool_dynamic.py:332 computes degree = adjacency.sum(dim=-1) without masking
    padded rows/cols.
  - pool_dynamic.py:333-335 uses that degree in the mincut denominator.
  - graph_utils.py:239-240 masks fine edges before coarse adjacency, so the same
    padded edge does not affect pooled_adjacency. This makes the loss corruption
    easy to miss.
Dependency note:
  - GraphMotionBatch rejects padded adjacency pollution at batch.py:466-472.
    That protects the collate path, but it does not seal DynamicGraphPool's
    direct API or its own fail-loud contract.
Test-suite gap:
  - tests/test_pool_dynamic.py:148-174 covers padded joint assignment with padded
    adjacency rows initialized to zero at tests/test_pool_dynamic.py:157-160.
  - There is no test that inserts a non-zero padded adjacency edge and expects
    either a ValueError or invariant mincut loss.

Concrete probe:
  - Setup: J_max=8, J_valid=6, line graph on valid joints. Add only one polluted
    padded edge adj[0,0,7] = adj[0,7,0] = 1.0.
  - Forward accepts the polluted adjacency.
  - assignment_equal True
  - pooled_adj_equal True
  - mincut_cut_clean -0.9097329378128052
  - mincut_cut_bad   -0.8132305145263672
  - mincut_clean     -0.4387211501598358
  - mincut_bad       -0.3904699385166168

Required fix:
  - Either reject any non-zero adjacency in padded rows/cols inside
    DynamicGraphPool.forward, or mask adjacency by joint_mask before every aux
    loss computation, including degree. Prefer fail-loud rejection to match the
    rest of this module.
  - Add a regression test that pollutes a padded row/col and expects ValueError,
    or, if masking is chosen, asserts mincut is identical to the clean case.
