Q3. R12 honest convergence scan
-------------------------------

Verdict: NEEDS-FIX. I found one concrete runnable failure trace.

Concrete blocker: padded frames are marked invalid by `frame_mask_recovered`,
but `GraphMotionVAE.decode` returns non-zero `pred_pos` on those invalid frames.

Why this is a VAE output bug, not speculation:

- `src/models/motion_decoder.py:195-197` masks the feature path by
  `frame_mask` before returning features to the FK head.
- `src/models/treeik_decoder.py:227-234` also masks TreeIK block activations by
  frame and joint mask.
- `src/models/graph_salad/vae.py:376-380` then applies the rotation head and FK.
  The rotation head has an identity-rotation bias, so zero invalid-frame
  features become identity local rotations.
- `src/models/treeik_decoder.py:114` masks FK output by `joint_mask` only, not
  by `frame_mask`.
- `src/models/graph_salad/vae.py:387-390` returns `pred_pos` and
  `frame_mask_recovered` without reapplying the frame mask to `pred_pos`.

Runnable repro:
