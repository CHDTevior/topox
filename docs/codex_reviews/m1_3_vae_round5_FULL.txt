Q2. Honest convergence: any concrete R12 runnable failure trace remaining?
-------------------------------------------------------------------------

Verdict: NEEDS-FIX. One concrete runnable failure remains.

Finding: `temporal_kernel` is now strict positive int, but even positive values
are accepted by `GraphMotionVAE` even though the temporal residual convs require
length-preserving kernels. With `temporal_kernel=2`, the constructor succeeds
and the first encoder temporal block crashes at runtime with a raw PyTorch shape
mismatch.

Source cause:

- `src/models/graph_salad/vae.py:101-117` validates only strict positive int for
  `temporal_kernel`; it does not require odd kernel size.
- `src/models/encoder.py:105-113` uses `padding = (kernel_size - 1) // 2` twice.
  For `kernel_size=2`, length changes from T=8 to T=6 after two convs.
- `src/models/encoder.py:123-130` then multiplies by the original `[B*J, T=8]`
  mask, causing the raw shape mismatch before the residual add.
- `src/models/motion_decoder.py:76-93` uses the same even-kernel-sensitive
  residual temporal conv pattern downstream.
