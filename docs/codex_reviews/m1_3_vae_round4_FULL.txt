Q2. Fresh R12 convergence scan
------------------------------

Verdict: NOT sealed. One concrete R12-grade bug remains with runnable trace.

Bug: GraphMotionVAE does not validate model dimension / head arguments before
using them.

Evidence:
- src/models/graph_salad/vae.py:96-99 validates `temporal_stride` as strict int
  and positive.
- src/models/graph_salad/vae.py:101-102 validates `dropout`.
- src/models/graph_salad/vae.py:103 immediately computes `d_model % n_heads`.
- There is no preceding strict-int / positive guard for `d_model`, `n_heads`,
  `d_ff`, layer counts, or treeik layer count.
- tests/test_vae.py:149-151 covers only the non-divisible case
  `d_model=17, n_heads=4`.
- tests/test_vae.py does not cover `n_heads=0`, `n_heads=True`,
  `n_heads=4.0`, or `d_model=0`.

Runnable failure trace:

```bash
cd /iridisfs/scratch/ts1v23/workspace/noKslot_clean
python - <<'PY'
from src.models.graph_salad.vae import GraphMotionVAE
GraphMotionVAE(pool_type="none", d_model=32, n_heads=0)
PY
```

Expected/current error:

```text
ZeroDivisionError: integer modulo by zero
```

Why this is R12-grade:
- The user explicitly listed division by zero and unvalidated input as R12 scan
  targets.
- This is a VAE-boundary input validation bug, not a downstream numerical
  artifact.
- It is not covered by an explicit test.
- It is easy to make fail-loud with a clear `TypeError` / `ValueError` before
  vae.py:103.

Additional probe: `d_model=0` is accepted by the constructor and emits PyTorch
zero-element tensor warnings. `n_heads=True`, `n_heads=4.0`, and
`d_model=32.0` fail later with raw PyTorch constructor `TypeError`s rather than
VAE-level validation.

Other R12 scan notes:
- No silent try/except fallback exists in vae.py.
- No-pool T divisibility now fails loud at vae.py:249-253 and is tested at
  tests/test_vae.py:153-166.
- Dropout range is tested at tests/test_vae.py:143-147.
- d_model/n_heads non-divisibility is tested at tests/test_vae.py:149-151.
- Dynamic/deterministic pool paths delegate shape/mask validation to the poolers.
- Real ckpt dim inference fails loud through key lookup or load_state_dict; no
  broad exception swallowing was found in tests/test_vae.py:188-205.
- I found no additional runnable VAE-only NaN-with-zero-gradient or mask-leak
  trace in this pass.

Recommended one-blocker fix:
- Add strict positive-int validation in GraphMotionVAE.__init__ before line 103
  for at least `d_model`, `n_heads`, `d_ff`, `n_graph_layers`,
  `n_enc_temporal_layers`, `n_cross_layers`, `n_dec_temporal_layers`,
  `n_treeik_layers`, `motion_feat_dim`, and `joint_feat_dim`.
- Add tests for `n_heads=0`, `n_heads=True`, `n_heads=4.0`, and `d_model=0`.
- Then rerun `python tests/test_vae.py`.
