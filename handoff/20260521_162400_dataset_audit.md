## §8 Critical findings for M1.5R / Phase 2

### ✓ Strengths

1. **Multi-topology** (J=18-143, 39 species) — true cross-skeleton benchmark, rare in motion-gen literature.
2. **Canonical name vocab + name_embeddings** — built-in cross-species shared semantics (28-38 species share core joints).
3. **Comprehensive features** (pos, vel, acc, rot6d, foot_contact, bone_lengths, root) — model can be re-purposed for many tasks.
4. **Clean train/val cross-topology split** — held-out species ensure true zero-shot generalization test.
5. **Pre-computed graph features** (parent_indices, adjacency, geodesic_dist, depths, degrees) — graph_salad can use without runtime overhead.

### ❌ Weaknesses (relevant to frozen-pred + future work)

1. **Heavy long tail**: median 13 clips/species, 4 species with <10. Per-species mu spread limited.
2. **High species-unique name rate (67%)**: name_embed mostly helps shared joints, not chains.
3. **Frame count cutoff (min_frames=16)**: dropped 38% (443) of raw BVH. **This is the M1.6+ trigger for data expansion**.
4. **No per-species motion-scale normalization in loss**: Tukan (0.07 m/s) vs Dragon (6.6 m/s) — 100× spread. Active species dominate vel loss, static species over-penalized for any motion.
5. **`max_frames=64` in training** truncates 32% of clips — long-action species (Anaconda, Spider with T=196 max) cut to 64 frames.
6. **Held-out species choice (Trex/Spider/Dragon)** has issues:
   - Trex (J=61): most clips in val → main eval target
   - Spider (J=71): mid-size
   - Dragon (J=143): EXTREME J → tests far-out-of-distribution joint count
   - But ALL three are train-zero → model never saw their topologies → very hard zero-shot
7. **foot_contact field** likely unreliable cross-species (assumes 4-limb mammal pattern, doesn't fit Anaconda/Spider/Centipede).

## §9 Recommendations for M1.5R (based on this audit)

### Pre-launch data prep (high confidence, codex-reviewable)

1. **Re-run preprocess with `min_frames=8`** (was M1.5R plan): expected 710 → 1000-1050 motions. Restores short clips (0.4-0.8s) that are still meaningful for motion VAE.
2. **Consider `max_frames=128`** in training (was 64): retains motion variety from long clips. But: longer T = larger batch memory. With B=16 + J=160 + d_model=384, T=128 may need OOM check on A100.
3. **Enable `use_name_embed=True`** (Codex D prong): leverage existing `name_embeddings`. Free win for cross-species generalization.
4. **Add per-species vel normalization in loss** (NEW): divide vel loss by species's median vel scale → static species (Tukan) and active species (Trex) get balanced gradient. ~20 LoC change.

### Held-out strategy considerations

5. **Reconsider held-out species** for M1.5R:
   - Current: ALL Trex/Spider/Dragon held out → very hard zero-shot.
   - Alternative: hold out a few clips per species but train on all 39 → easier in-distribution + standard transfer test. Better for M1.5 acceptance (motion fidelity); save zero-shot test for M2.
   - User decision needed.

### Don't change

6. **Don't change canonical_names** — vocab is stable, name_embeddings are pre-computed against it.
7. **Don't change root_position / root_velocity convention** — model uses these.
