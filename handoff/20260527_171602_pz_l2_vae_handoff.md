## §8 失败经验 + 教训 (cross-project + 本 session)

### 8.1 ckpt 命名 + alloc 监控

**故事**: 老 alloc 925437/925436 5d walltime 到期 silently 杀进程,我 ckpt 渲染脚本 srun 进死 alloc 写出 "Invalid job id" 错。

**教训**: 启动 srun 前必查 `squeue -j <id> -t RUNNING`,don't assume alive。

### 8.2 cond cache pickle env 跨 env 不兼容

**故事**: 我在 login env 测 cond cache, pickle 用 numpy 2.x;graph_salad env 用 numpy 1.x,unpickle 报 `numpy._core.numeric` 不存在。

**教训**: **数据缓存必须在用它的同环境下生成**。永远不要从 login env build cache 给 conda env 用。

### 8.3 DDP cond cache race (codex P0→P1→PASS)

**故事**: 初版 `tmp_path = cache.with_suffix(".pkl.tmp")` 4 rank 共享同 tmp 文件,DDP race 可破坏 cache。Per-PID 仍跨 host 撞名。最终用 `tempfile.NamedTemporaryFile(dir=parent, prefix=..., delete=False)` 全局唯一。

**教训**: DDP race-safe 写文件必须**文件系统全局唯一 tmp** + atomic rename。PID 不够。

### 8.4 Cross-alloc DDP 第一次尝试失败 (NCCL CUDA error)

**故事**: 跨 925443+925444 (同节点不同 alloc) 默认 NCCL P2P/SHM → cgroup 阻挡 → `ncclUnhandledCudaError`。

**教训**: 跨 cgroup 必 force TCP: `NCCL_P2P_DISABLE=1 NCCL_SHM_DISABLE=1 NCCL_SOCKET_IFNAME=ib0`。NVLink/SHM 不能跨 cgroup 即使物理同节点。

### 8.5 88MB caption JSON 默认加载阻塞 init

**故事**: PlanetZoo L1 dir 有 88MB caption JSON,AnyTopDataset 默认 `load_captions=True` 每 rank × 每 dataset 都 json.load → 5-10 min stall。

**教训**: 大数据集 init 必查"我真的需要这个文件吗"。改用 `load_captions=bool(args.use_text)` gating。

### 8.6 cond_normalize O(J²) pure-Python 慢

**故事**: PlanetZoo 473 object_types × J=210 → `_create_topology_edge_relations` + Floyd 共 ~107s 单进程。4 rank × 2 ds × CPU 争用 → 25 min 等待。

**教训**: 对超出 70 个 cond entries 的数据集必先 build disk cache。已实现 in `src/data/anytop_dataset.py` L508+。

### 8.7 NaN loss 在 lr=7e-4 DDP H200 (v3 denoiser)

**故事**: v3 4000ep DDP H200 训练 lr=7e-4 (sub-linear sqrt(2)) 在 ep1343 一次 batch NaN,损失 1343 ep 进度。诊断 (`_diag_v3_nan.py`) 表明: 32 个具体 sample 单独跑都正常,是随机 noise/timestep × batch state 组合的数值边界。

**教训**: lr 不是单独决定,**与 DDP global batch + 模型容量同步**;v1/v2 single-card lr=5e-4 3000ep 从未 NaN,所以 5e-4 是"硬保险"。每加 DDP / batch 大幅,优先保守不激进。

### 8.8 batch=64 per-rank OOM 早期

**故事**: A100 4-card 配 d_model=512 + max_coarse=128 + max_joints=144, smoke per-rank=64 OOM,per-rank=48 也 OOM,per-rank=32 79GB 临界 OK。

**教训**: attention 激活 ~ B×heads×C²×T_lat 主导显存。max_coarse 是大头。**先 binary-search 找 max stable per-rank,再设 lr**。

### 8.9 T2M overshoot 不是 CFG 单独问题

**故事**: 多 ckpt + 多 CFG 实验后确认: Dragon Die caption sr=3-7 是 model bias on low-velocity captions,不是 CFG 放大,不是 max_frames=64 vs 260 引起。

**教训**: T2M 系统性 overshoot 跟训练数据 motion magnitude 分布有关 (idle/die 样本少)。**CFG=1.5-2.0 改善但治标不治本**。

### 8.10 删 ckpt 必先盘点 (cross-project safety)

**故事**: cleanup 20GB → 5.5GB 之前 user 确认 4 个 tier。

**教训**: 删 ckpt 是 destructive op,跨 project rule 要求**先列分级 + AskUserQuestion 确认**才删。

### 8.11 session context 爆炸 (本 session)

**故事**: 本 session 跑了 Pool v2 + 多 denoiser + L2 VAE + bench 一连串,context 接近极限,用户要 handoff。

**教训**: **早期 rotate,不要等 hang**。一旦 handoff 文件 >40KB 或 >8 codex review,就该 rotate session 而非继续 inline。

### 8.12 不要 self-submit Slurm allocs (iron rule)

**故事**: 我不能用 `sbatch`,user 申请新 alloc。我只能 `srun --jobid=X --overlap` 进已有 alloc。

**教训**: alloc 管理永远 user 手动,我**只能用**已有 alloc。alloc 用完 user 再开新的。
