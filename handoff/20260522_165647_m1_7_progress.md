## §5 graph_temporal A/B 结论(Run B 完成,Run A 后台跑)

**Run B(DDP, lr4e-4)完成**:
- best_recon ckpt @ **ep299**, val_recon = **2.2781**(对照 coarse_xattn ep829 val_recon **2.0442**)
- **Δ = +11.4% 劣于 coarse_xattn**;ep900-999 val 已漂到 2.43-2.47(过拟合)
- 视觉(QA gif):无骨架灾难,但**一致 over-shoot 位移幅度**(Alligator f63: GT 1.007 → ddp 1.219 = +21%, coarse_xattn 1.032 = +2.5%;Trex 各帧 +9-15%)。metric 退化主要来自位移过冲,不是塌缩。
- 归因:**架构容量过大 + DDP 全局 batch 32 削弱隐式正则** 两重叠加 → 过拟合

**Run B 已 lr8e-4 异常 → kill → lr4e-4 重启;lr4e-4 重启后单调下降稳定**(ep0→ep999 train_loss 14.05→0.97 全程单调)。这是个独立教训:**AdamW + 小 batch 的隐式正则**是它能稳的关键之一,大 batch DDP 化需要补 weight decay / dropout 来抵消。

**Run A(单卡, batch16)还在 ep~440/1000**,~12.5h 到 ep1000。Run A 才是**纯架构对照**(同 batch 16 vs coarse_xattn 同 batch 16),可拆开「架构 vs DDP/batch」两个变量:
- 若 Run A best_recon ≈ 2.28 → 锁定**架构**是主因(graph_temporal 真不行)
- 若 Run A best_recon ≈ 2.04-2.10 → **DDP/batch** 是主因,架构本身 OK,Phase 2 时若 DDP 化需补正则

**决定:**
1. **`coarse_xattn` 锁定为 Phase 2 backbone 的 decoder**(val_recon 2.04 已证)。
2. **graph_temporal 架构暂存**:当前 855 训练样本小数据集上易过拟合;**待数据增广(remove-joints aug 启用、可能未来 add_joints / 跨数据集)后重试**,看大数据是否能撑住这个容量。**不删代码、不改默认**(`decoder_mode=graph_temporal` 仍是可选 flag,可随时再用)。
3. Run A 跑完后做最终归因报告 + tear down /loop。
